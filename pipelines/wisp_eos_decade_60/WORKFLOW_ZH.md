## 一句话流程

**先集中处理一个 cube 的 120 个月，再预测这个 cube 的全部日期；验证结果、
清理临时输入后，才轮到下一个 cube。** 不是 15 个 cube 各开 60 个作业。

```mermaid
flowchart LR
    A[原始数据] --> B[60作业 × 2月份进程]
    B --> C[完整十年输入验收]
    C --> D[A100 / batch 8]
    D --> E[十年NetCDF验收]
    E --> F[等待10分钟后独立清理]
    F --> G[下一个cube]
```

## 固定资源与数值规则

- 最多 60 个 CPU 作业，每作业 4 CPU、16 GiB，时限 24 小时。
- 每作业两个独立进程，各自独占一个月份；月内日期顺序处理，复用历史窗口。
- CPU 分区 `work,small,gpu`，不使用 `big`；CPU 建输入不占 GPU 设备。
- 包含控制、验收、清理在内，总排队＋运行任务不超过 120 个。
- 预测期 2014-01-12—2023-12-31，共 3,641 天；第一天天气从 2014-01-08 开始。
- 每天读取 `[t0−96小时,t0+24小时)`，每个月独立准备跨月背景。
- 使用原训练 mean/std、冻结辐射窗口归一化和两次 float16 转换；不重算新数据均值方差。
- 使用真实 VIIRS 历史，不递归反馈。未来火情、FRP、植被不能进入输入。
- 模型 EOS corrected/Q10/seed42/epoch46；一张 A100、batch=8。
- 输入 128×128，输出中心 96×96；连续分数不是实测烧毁面积或 CO₂ 排放。


旧运行的预测和其他 cube 的暂停检查点保留；它们也计入 1 TiB 缓存预算。

## 如何判断进度？

- `reports/progress.json`：当前 cube、阶段、月份和作业状态。
- `state/job_resources/`：实际内存与 CPU 使用；不能把申请量当作使用量。
- `reports/pilot_passed.json`：扩至 60 作业的验收依据。
- `reports/regions/`：最终结果验收；不是作业退出就算完成。
- `campaigns/granada_plus15_20261104/complete.json`：本次全部 16 个完成后的标志。

“120 个月正在处理”不等于“120 个月处理完成”。由于月份之间速度差异很大，
不能只用总体完成百分比线性推算结束时间；最后要等待最慢月份。

英文 README 提供完整输入张量、部署、恢复、测试和控制器交接命令。
仓库中的 `engine/` 是运行版本的精确归档；数值代码、原始数据、权重和冻结环境
在 Jena 共享目录中只读引用，不能在任意机器上直接运行而省略这些依赖。
